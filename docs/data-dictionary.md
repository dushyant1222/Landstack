# LandStack — Data Dictionary (as implemented, Flyway V1–V8)

All IDs are `UUID` (generated by the app with `UUID.randomUUID()`). All timestamps are `TIMESTAMPTZ`,
written in UTC. Status columns use `CHECK` constraints. Tables are created by Flyway in the module
listed.

## 1. Entity relationships

```
app_user 1─* import_job *─1 source_file
import_job 1─* processing_attempt
import_job 1─* import_row            (staging; purged after expiry)
import_job *─1 field_mapping_template (optional, the template used)
import_job 1─1 import_mapping         (exact mapping snapshot used)
import_job 1─* land_record            (lineage: source_file_id + import_job_id + source_row_number)
land_record 1─* land_record_source_value
land_record 1─* quality_issue
app_user 1─* audit_event (actor)
```

## 3. Canonical fields (mapping targets)

`parcel_id, survey_khasra_no, owner_name, land_area_value, land_area_unit, land_type,
registration_ref, registration_date, village_locality, tehsil, district, state, latitude, longitude,
geometry`. All fields are optional at the schema level. A **dataset profile** (default: "at least one
of parcel_id / survey_khasra_no, plus district") sets which fields are required for a given import.

Known aliases (used only to *suggest* a mapping, which the operator must confirm):
`ULPIN, Parcel ID, Bhu-Aadhaar → parcel_id`; `Khasra No, Survey No, Khasra/Survey → survey_khasra_no`;
`Owner, Khatedar, Owner Name → owner_name`; `Area → land_area_value`; `Unit, Area Unit →
land_area_unit`; `Village, Locality, Mauza → village_locality`; `Lat, Latitude`; `Lon, Lng, Long,
Longitude`; and so on (full table in Module 7).

## 5. Placeholder policy (norm-1.0)

These values, after trimming and case-insensitive comparison, are treated as **missing** (stored as null, with
the raw value kept in `land_record_source_value`): `""`, `-`, `--`, `N/A`, `NA`, `nil`, `null`,
`none`, `not available`. Configurable.

Supported date formats: `yyyy-MM-dd`, `dd-MM-yyyy`, `dd/MM/yyyy`, `dd.MM.yyyy`. Inputs where day and
month could be swapped are parsed as the Indian day-first convention **only** when the dataset
profile declares day-first. Otherwise they are flagged `DATE_AMBIGUOUS` and left null.

## 6. Rule-based quality checks (v1 catalogue)

| rule_id | Field | Severity | Stage |
|---|---|---|---|
| ID_MISSING | parcel_id/survey_khasra_no | HIGH (blocking per profile) | preview |
| LOCALITY_MISSING | district/village | WARNING | preview |
| AREA_NEGATIVE | land_area_value | HIGH (blocking) | preview |
| AREA_NOT_NUMERIC | land_area_value | HIGH (blocking) | preview |
| AREA_EXTREME | land_area_sqm | WARNING (thresholds configurable) | both |
| UNIT_MISSING / UNIT_NOT_CONVERTIBLE | land_area_unit | WARNING | preview |
| DATE_INVALID / DATE_AMBIGUOUS | registration_date | WARNING | preview |
| COORD_OUT_OF_RANGE | latitude/longitude | WARNING (coordinates nulled, raw kept) | preview |
| COORD_PARTIAL | latitude/longitude | WARNING | preview |
| DUP_ROW_IN_FILE | row | WARNING | preview |
| DUP_PARCEL_IN_SCOPE | parcel_id + village + district | WARNING | post-confirm |
| DUP_KHASRA_IN_SCOPE | survey_khasra_no + village + district | WARNING | post-confirm |
| DUP_CONFLICTING_AREA | land_area_sqm across duplicate candidates | WARNING | post-confirm |
| DUP_CONFLICTING_FIELDS | owner/type across duplicate candidates | INFO | post-confirm |
| EXTRACTION_LOW_CONFIDENCE | any PDF-derived field | WARNING | preview |
| FIELD_UNMAPPED_REQUIRED | profile-required field | mapping rejected (422) | mapping |
| UNIT_UNKNOWN | land_area_unit | WARNING | preview |
| COORD_INVALID / COORD_ZERO | latitude/longitude | WARNING | preview |
| GEOMETRY_INVALID | geometry | WARNING | preview |
| DUP_IDENTICAL_ROW | row | WARNING | preview |
| LAND_TYPE_UNMAPPED | land_type | INFO | preview |
| STAT_AREA_IQR | land_area_value | INFO (advisory, source STATISTICAL) | on demand |

"Blocking" means the row cannot be selected for confirmation until it is corrected. All other flags are
informational and go to human review.
